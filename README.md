# Taskbar Volume — регулировка громкости скроллом над панелью задач

Аналог Volume2 для Windows 11/10. Портабельное приложение в одном `.exe`,
работает **без прав администратора**.

**Скачать: [TaskbarVolume.exe](https://github.com/Gypopo118/TaskbarVolume/releases/latest)** (~16 МБ, без консоли,
без установщика). Можно скопировать куда угодно и запустить двойным щелчком.
После сборки из исходников exe лежит в `dist\TaskbarVolume.exe`.

## Как работает

- Наведи курсор на панель задач (основную или на любом дополнительном мониторе).
- Крути колесо: вверх — громче, вниз — тише. Прокрутка самой панели при этом блокируется.
- Появляется OSD-капсула (200×70 в логических px — ширина уменьшена на треть
  относительно прежней 300×70) с динамиком, процентом и полосой. Она приклеена нижним
  краем к верхней кромке панели задач и после появления **не двигается за курсором**:
  пока OSD виден, колесо обновляет только процент и полосу, а позиция остаётся
  фиксированной. Через 1 с после последнего скролла капсула плавно исчезает.
- Иконка в трее показывает уровень громкости зелёной заливкой снизу вверх; при 0% / mute — белый крестик.
- ПКМ по иконке: **Автозапуск при входе**, **Настройки…**, **Выход**.

## Быстрый старт

```bat
TaskbarVolume.exe
```

Если иконки не видно рядом с часами — нажми `^` в области уведомлений (Windows 11
по умолчанию прячет новые иконки в переполнение) или включи её в
**Параметры → Персонализация → Панель задач → Другие значки в области уведомлений**.

Автозапуск можно включить галочкой в меню трея, в окне настроек или из командной строки:

```bat
TaskbarVolume.exe --enable-autostart
TaskbarVolume.exe --disable-autostart
TaskbarVolume.exe --autostart-status
```

Запись создаётся в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\TaskbarVolume`:

```
"C:\...\TaskbarVolume.exe" --autostart
```

Права администратора не нужны. Если перенести exe в другое место, автозапуск нужно
включить заново (запись хранит полный путь). При входе в Windows приложение стартует
в трее без окон и с задержкой 1.5 с, чтобы проводник успел загрузиться.

## Проверка и тесты

### 1. Самодиагностика (встроена в exe)

```bat
TaskbarVolume.exe --diagnose
```

Проверяет DPI-awareness, конфиг, автозапуск, Core Audio, поиск панели задач,
установку/снятие хука без прав администратора, отрисовку иконки трея и создание OSD.
Открывается консоль, в конце печатается путь к отчёту (по умолчанию
`%TEMP%\TaskbarVolume\diagnose.txt`). Код возврата `0` — всё в порядке.

Можно указать свой путь:

```bat
dist\TaskbarVolume.exe --diagnose --diagnose-report C:\Temp\tv.txt
```

### 2. End-to-end тест (двигает реальную мышь и проверяет OSD по скриншоту)

```bat
python tools\e2e_test.py
```

Тест сам запускает `dist\TaskbarVolume.exe` (если он собран, иначе `main.py`), ставит
громкость 50%, наводит курсор на панель задач и отправляет колесо через `SendInput`.
Проверяется:

1. приложение реагирует на колесо;
2. 50% → 53%;
3. OSD с зелёной полосой реально виден на скриншоте, а его низ совпадает
   с верхним краем панели задач;
4. при движении курсора вдоль панели громкость продолжает меняться (53% → 57%),
   но OSD остаётся в начальной точке (проверяется по RECT окна);
5. колесо вниз: 57% → 53%;
6. колесо вверх снимает mute;
7. колесо вне панели задач громкость не меняет;
8. второй экземпляр молча завершается (single instance);
9. `--enable-autostart` / `--disable-autostart` пишут и удаляют запись в реестре;
10. приложение завершается по внутренней команде выхода без зависших процессов.

Исходная громкость, mute и запись автозапуска восстанавливаются. Нужен интерактивный
рабочий стол (не заблокированный экран). Варианты:

```bat
python tools\e2e_test.py --source          :: тестировать main.py, а не exe
python tools\e2e_test.py --no-launch       :: приложение уже запущено
python tools\e2e_test.py --skip-autostart
```

### 3. Юнит- и интеграционные тесты

```bat
python -m unittest discover -s tests -v
```

- `test_volume_steps.py` — таблица шагов, 0↔100, округление, границы;
- `test_config.py` — портабельный конфиг, валидация, клоунинг значений;
- `test_taskbar.py` — реальные окна панели задач, зоны, скорость кеша;
- `test_volume_com.py` — чтение/запись Core Audio и mute (пропускается без звуковой карты).

## Сборка exe из исходников

Требования: **Python 3.10+** (сборка проверена на 3.12 и 3.14), Windows 10/11.

```bat
build.bat
```

или:

```powershell
.\build.ps1
```

Скрипт ставит `pystray`, `Pillow`, `PyInstaller` и собирает
`dist\TaskbarVolume.exe` по спеке [`TaskbarVolume.spec`](TaskbarVolume.spec)
(onefile, windowed, иконка, версия 1.2.1.0, без UPX).

Ручная сборка:

```bat
python -m pip install -r requirements.txt pyinstaller
python -m PyInstaller --noconfirm --clean TaskbarVolume.spec
```

Запуск из исходников:

```bat
python -m pip install -r requirements.txt
python main.py
```

или `run.bat` (через `pythonw`, без консоли).

## Конфигурация

Портабельный режим: положите `config.json` **рядом с exe** — приложение возьмёт его.
Иначе используется `%APPDATA%\TaskbarVolume\config.json`.

```json
{
  "osd_duration_ms": 1000,
  "fade_duration_ms": 200,
  "autohide_edge_px": 5
}
```

- `osd_duration_ms` — сколько OSD висит до начала исчезновения (100…10000);
- `fade_duration_ms` — длительность затухания (50…2000);
- `autohide_edge_px` — толщина зоны у края экрана для автоскрытой панели (0…30).

Значения вне диапазона аккуратно клампятся. Настройки из меню «Настройки…» сохраняются
в тот же файл. Переменная окружения `TASKBAR_VOLUME_CONFIG` перекрывает путь
(используется тестами).

Лог: `%APPDATA%\TaskbarVolume\TaskbarVolume.log` (ротация 512 КБ × 1).

## Архитектура

```
main.py              — точка входа, очередь событий, single instance, CLI
volume_controller.py — Core Audio через raw COM (ctypes), без comtypes
taskbar_detector.py  — окна панели задач + мониторы + автоскрытие, кеш 0.35 с
osd.py               — капсула Tk: DPI-масштаб, скругления, fade, topmost-оверлей,
                       привязка к кромке панели и фиксированная позиция
tray_icon.py         — иконка Pillow + pystray, меню и checked-автозапуск
settings_window.py   — тёмное окно настроек, проверка OSD, автозапуск
config.py            — конфиг, пути, логирование, HKCU Run
mouse_hook.py        — WH_MOUSE_LL, аккумулятор дробных дельт тачпада
dpi.py               — Per-Monitor V2, мониторы, DPI для точки
win_utils.py         — MessageBox, мьютекс, консоль, возврат фокуса
diagnostics.py       — --diagnose
TaskbarVolume.spec   — сборка onefile
tools/e2e_test.py    — end-to-end проверка колеса/OSD/автозапуска
tools/make_icon.py   — генерация icon.png / icon.ico
tests/               — unittest
```

Потоки:

- **главный** — Tk (скрытый root, OSD-Toplevel, настройки) и обработка очереди;
- **MouseHook** — `WH_MOUSE_LL` + `GetMessage`-цикл; только проверяет зону и кладёт событие;
- **Tray** — `pystray.Icon.run()`; пункты меню кладут события, не трогая Tk.

COM (Core Audio) живёт в главном STA-потоке: громкость читается/пишется оттуда же,
поэтому нет гонок между хуком, Tk и аудио.

## Что исправлено относительно исходной версии

- **Громкость не работала вообще**: `from ctypes.wintypes import HRESULT` падал на Python 3.12+,
  а объявленные вручную COM-интерфейсы `comtypes` имели неверные индексы vtable
  (`GetMasterVolumeLevelScalar` попадал в `RegisterControlChangeNotify`). Теперь Core Audio
  вызывается напрямую через `ctypes` с правильными слотами `IMMDeviceEnumerator` /
  `IMMDevice` / `IAudioEndpointVolume`; зависимость `comtypes` больше не нужна.
- **Tk из чужого потока**: старый код создавал OSD в отдельном потоке и вызывал `after()`
  из хука. Теперь весь Tk — в главном потоке, хук только кладёт события в очередь.
- **OSD был под окнами и крал фокус**: добавлен отдельный Toplevel с
  `WS_EX_NOACTIVATE|WS_EX_TOOLWINDOW`, `SetWindowPos(HWND_TOPMOST)` на каждом показе;
  фокус активного окна сохраняется (проверено).
- **Портабельный config.json** из ТЗ не был реализован — реализован.
- **Автозапуск из исходников** прописывал `.py`-файл как исполняемый — теперь
  `pythonw.exe main.py --autostart`; для exe команда `"путь\TaskbarVolume.exe" --autostart`.
- **Хук на 64-bit**: не были заданы `argtypes/restype` для `SetWindowsHookExW`,
  `CallNextHookEx` и `GetMessageW` — handle мог обрезаться до 32 бит. Исправлено,
  добавлен аккумулятор дробных дельт тачпада.
- **Мультимонитор/DPI**: координаты хука и окон сверяются в физических пикселях
  (`SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`), OSD масштабируется по DPI
  монитора под курсором и клампится в его границы.
- Добавлены логирование, single instance, окно настроек, самодиагностика,
  тесты и корректное завершение (хук снимается, трей останавливается).

## Известные ограничения

- Windows 11 допускает панель задач только внизу; для Windows 10 снизу/сверху/по бокам
  видимая панель определяется по `GetWindowRect`, автоскрытая — по краю монитора.
- Если полноэкранное приложение перекрывает панель задач, зона панели всё равно
  считается активной (окно `Shell_TrayWnd` существует) — это поведение Volume2-подобных утилит.
- Антивирусы иногда реагируют на `SetWindowsHookExW` — это нормально для глобальных хуков;
  exe не подписан.
- Иконка трея в Windows 11 по умолчанию попадает в переполнение `^`.
- Очень быстрый скролл обрабатывается очередью; шаг остаётся 3–4%, как в ТЗ.
